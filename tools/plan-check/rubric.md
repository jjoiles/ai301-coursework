# Rubric: is this plan ready to post and build from?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Diagnosis grounded in evidence | Compare the plan's stated cause and problem explanation with the repro evidence's observed results, commands, errors, and issue context. | Pass if the diagnosis is consistent with the reproduced behavior, distinguishes observations from hypotheses, and does not assert an unsupported root cause as proven. A tentative diagnosis passes when it identifies what must be verified before implementation. Fail if the diagnosis contradicts the evidence or ignores a material result. | required |
| Bounded change | Compare the plan's scope, intended code changes, and exclusions against the issue's requested behavior and repo-facts block. | Pass if the proposed work is one coherent, bounded change addressing the issue, without unrelated features or unnecessary refactoring. Necessary supporting edits and tests may be included. Fail if the proposed work expands into unrelated behavior or leaves the intended change too broad to evaluate. | required |
| Cause-directed approach | Compare the plan's proposed implementation steps and target code paths with its diagnosis, the repro evidence, and relevant repository facts. | Pass if the proposed approach addresses a plausible cause of the reproduced problem rather than merely hiding its symptoms. When the cause is uncertain, pass if the plan includes a concrete verification step before choosing the implementation. Fail if the approach only suppresses the failure or changes unrelated behavior. | required |
| Executable implementation steps | Compare the plan's ordered actions, named files or components, prerequisites, and verification steps with the repository facts and reproduction setup. | Pass if a contributor familiar with the repository can identify where to begin, what to inspect or change, and how to proceed without inventing essential implementation decisions. Minor details reasonably discoverable in the repository do not cause failure. Fail if essential starting information or decisions are missing. | required |
| Observable test strategy | Compare the plan's proposed tests and expected outcomes with the reproduction evidence's commands, inputs, and observed failure. | Pass if the tests or checks exercise the relevant code path and can distinguish the reported faulty behavior from the intended behavior. A relevant existing regression test or a concrete before-and-after check is sufficient. Fail if the tests are unrelated, purely cosmetic, or cannot demonstrate whether the change worked. | required |
| Honest uncertainties and risks | Compare the plan's claims, assumptions, dependencies, and unresolved questions with the issue context, reproduction evidence, and repository facts. | Pass if material unknowns are acknowledged and the plan explains how they will be investigated or handled before they affect the implementation. Do not require speculative risks when the evidence supports a straightforward change. Fail if a material uncertainty is presented as a verified fact or an unresolved blocker is ignored. | required |
| Thread and repository conventions | Compare the proposed plan comment with the issue's thread highlights, contributor instructions, repository conventions, and any applicable AI-disclosure policy in the repo-facts block. | Pass if the comment accurately describes the issue-specific intended work, respects relevant prior discussion and maintainer instructions, and follows applicable repository communication and disclosure requirements. If no applicable convention is stated, do not invent one. Fail if the comment contradicts a maintainer instruction, misrepresents the intended change, or omits required disclosure. | required |

## Verdict rule

Accept only when every required check passes. Reject if any required check fails or is unclear because the available evidence is insufficient to establish the pass condition. Preferred checks, if introduced later, provide feedback but never change the binary verdict. Do not reject solely for formatting, section count, writing style, or minor omissions that do not affect whether a stranger could safely begin the bounded change.
